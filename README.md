# Shape Param Lab（形状パラメータ・ラボ）

サロゲートモデルの学習データ用に、**CAD（STEP / IGES）やメッシュ（STL / Abaqus・CalculiX の .inp）の寸法をパラメータ化**し、
スライダーで形を変えて 3D で確認しながら、**実験計画（LHS など）に沿って形状を一括生成**するツール。

- 面をクリックして「板厚」「ボス高さ」「穴径」「リブ幅」などの寸法を定義（STL / INP は平面・円筒を自動認識）
- スライダーを動かすと、サーバ（OpenCascade）で形状を作り直して 0.2〜0.5 秒ほどで表示
- 範囲チェック（各寸法を最小・最大にしても形が作れるか）
- 寸法どうしの制約（例: `rib_h <= bossB_h - 3`）を満たす組み合わせだけで実験計画を作成
- 一括生成: `sample_001/geometry.stl + geometry.step（または .inp）+ conditions.csv` の形式で書き出し
  （ml-process-lab / surrogate-manager のデータフォルダ形式に合わせている）

## 起動

Windows では `start.bat` をダブルクリック（初回はライブラリ導入と画面ビルドを自動実行）→ http://127.0.0.1:8200

手動で起動する場合:
```bash
cd frontend && npm install && npm run build     # 初回のみ（画面のビルド）
cd backend && uv sync && uv run uvicorn server:app --host 127.0.0.1 --port 8200
```

前提: [uv](https://docs.astral.sh/uv/)（Python 3.11 は uv が自動取得）、Node.js 22.12 以上（初回ビルド時のみ）

### 開発時
```bash
cd backend && uv run uvicorn server:app --host 127.0.0.1 --port 8200 --reload
cd frontend && npm run dev     # http://localhost:5190（/api は 8200 へ転送）
cd backend && uv run pytest -q # テスト
```

## 使い方

画面の上に 4 つの手順が出ます。右側には、今の手順でやることだけが表示されます。

1. **形状を読み込む** — ファイル（STEP・IGES・STL・INP）を右の枠にドロップ。「デモ」ですぐ試せる
2. **変えたい所を選ぶ** — 3D の面をクリックすると、その場に候補が出る（例:「この穴の大きさ（直径）を変える いま φ12」
   「反対側の面と一緒に、両側へ均等に厚みを変える いま 6 mm」）。選ぶと寸法ができ、3D に矢印と数値が出る。
   **矢印の先の ● をドラッグ**するか、右のスライダーで形が変わる
3. **範囲を決める** — 寸法ごとに最小〜最大（±10/20/30% のボタンあり）。「端の値で作れるか確かめる」で事前確認。
   寸法どうしの条件（例: リブがボスより高くならない）は「詳細」に書ける
4. **形状を作る** — 作る数を決めて「○ 形状を作る」。組み合わせは自動で選ぶ（ラテン超方格）

寸法の種類・測る基準の面・係数・列名などは、各寸法の「詳細設定」で変えられる（ふだんは見なくてよい）。
設定は右上の「設定を保存」で `data/projects/<名前>.json` に残り、「① 読み込む」の「保存した設定から続ける」で再開できる。

### 実験計画の方法
| 方法 | 内容 |
|---|---|
| ラテン超方格（LHS） | 各寸法の範囲を形状数で等分し、どの区間も 1 回ずつ使う（標準。簡易 maximin で偏りも抑える） |
| ランダム | 一様乱数 |
| 格子 | 各寸法を水準数で等分した全組み合わせ |
| 1因子ずつ | 他を元の値に固定し 1 つずつ振る（感度確認） |

### 制約（寸法どうしの関係）
1 行に 1 つ、列名（key）を使った不等式を書く。使える記号は `+ - * / <= >= < > and or` と数値だけ。
```
rib_h <= bossB_h - 3        # リブ上面をボスB上面より 3mm 以上低く
hole_d <= bossA_d - 8       # 穴の周りの肉厚を 4mm 以上
```
LHS・ランダムでは、候補を多めに作って制約を満たすものから互いに離れた点を選ぶ。
メッシュ変形では「リブがボスより高くなる」ようなつながりが変わる組み合わせは作れないので、制約で除いておく。

### 出力
```
data/outputs/<出力名>/
  doe_table.csv        … 全サンプルの寸法・体積・表面積・方式・要素の最小体積比・成否（BOM 付き UTF-8）
  project.json         … 生成に使った定義とサンプル値（再現用）
  sample_001/
    geometry.stl       … 学習・ボクセル化用
    geometry.step      … CAE にそのまま渡す用（CAD 入力のとき）
    <元の名前>.inp      … 節点座標だけ書き換えた解析メッシュ（INP 入力のとき）
    conditions.csv     … name,value 形式の寸法（学習の入力条件）
    shape.json         … 寸法・各面の移動量・体積・メッシュ品質など
```
| 入力 | 出力できる形式 |
|---|---|
| STEP / IGES / BREP | STL・STEP |
| STL | STL |
| INP | INP・STL |
1 件失敗しても止まらず、`doe_table.csv` に `failed` と理由が残る。

## 形状の変え方（しくみ）

STEP には CAD の履歴（スケッチ寸法・フィーチャー）が残らないため、**ダイレクトモデリング**（面を動かす）で寸法を変える。

| 方式 | 内容 | 使われる場面 |
|---|---|---|
| 精密（面オフセット） | OpenCascade の `BRepOffset_MakeOffset` で選んだ面を法線方向に動かす。隣の面は自然に伸び縮みし、抜き勾配も保たれる | 単純な形 |
| 近似（押し出し/削り） | 平面はその面の押し出しを足す/削る、円筒面は筒を足す/削る（ブーリアン）。ボスを細くしたときは付いていたリブを新しい外径まで延ばす | 精密が失敗する形（**リブがボスに付く形**など、鋳物では多い） |

既定の「自動」は精密を試して、だめなら近似で作る。使った方式は画面と `doe_table.csv` に出る。
両方式が使える形では体積が一致することをテストで確認している（`backend/tests`）。

### メッシュ（STL / INP）の場合
**面の自動認識**（`backend/shapelab/recognize.py`）: 「面の式を当てはめながら広げる」方式。
1. 平面: 平らな三角形を種に、同じ平面に乗る三角形だけを広げる（大きい平面から順に）
2. 曲面: 残りの三角形に 円筒・円錐（抜き勾配）・球 を当てはめ、頂点が式の上（既定は形の大きさの 0.02%）に乗る三角形だけを広げる。
   広がるたびに頂点への最小二乗で軸・中心・半径・勾配を調整する
3. 小さな半径で短い円筒に見えるものは、トーラス（ボスの付け根の輪のフィレット）として当てはめ直す
4. 隣り合う同じ種類の面はまとめて当てはめ、合えば 1 つにする。曲面の一部が小さな平面として取られたものは曲面に戻す
5. 残り（自由曲面など）はつながりごとに「その他」

フィレットでなめらかにつながったボス・リブ・板も、頂点が式から外れる所で別の面に分かれる。
フィレット（トーラス・小半径で 1/4 円前後の円筒）は、寸法を変えると隣の面の動きを受け継いで一緒に動く（半径をほぼ保つ）。

確認した形（`backend/tests/test_mesh.py`）:
| 形 | 結果 |
|---|---|
| 角が立ったデモ（STL・C3D4・C3D10） | CAD と同じ 18 面（平面 15・円筒 3） |
| フィレット R1.5・抜き勾配ボス付き（C3D10） | 25 面（CAD 26 面）。ボス φ28・φ20、穴 φ12、勾配ボス（円錐 7.1°）、輪のフィレット 3、リブ付け根のフィレット 2 |
| 同じ形の細かい STL | 主な面はすべて正しい。リブ付け根のフィレットの一部が「その他」や小片になる |

前提: 頂点が実際の形の上にあること（CAD から作った STL、CAD に節点を載せた解析メッシュ）。
スキャンデータや、節点を平滑化したメッシュでは認識しにくい（許容誤差を大きくする必要がある）。

**メッシュ変形（モーフィング）**: 要素のつながりは変えずに節点だけ動かす。
1. 各節点に、乗っている面ごとの拘束をかける（動かす面は法線方向に移動量、動かさない平面・円筒は 0 ＝ 面の上をすべるだけ）
2. 3 面が交わる角は位置が決まる → 面の境界線は線に沿って均等に伸び縮み → 面の中はその面の境界を固定してなめらかに補間
3. INP の内部節点は表面を固定して補間
4. 表面の三角形や要素が裏返ったら失敗にする（`doe_table.csv` に理由。要素の最小体積比も記録）

係数行列は移動量によらないので最初に 1 回だけ分解し、スライダー操作は代入だけで解く
（約 20 万節点の C3D10 で初回 5 秒・以後 0.2 秒程度）。

**INP の対応範囲**: C3D4 / C3D10 / C3D8(R,I,H) / C3D20(R) / C3D6 / C3D15（DC3D… の熱伝導要素も可）、
シェル S3 / S4 / S6 / S8 / M3D… は表面として扱う。書き出しは `*NODE` の座標だけ書き換え、
セット・材料・ステップなど他の行はそのまま残す。

### 制限
- CAD 入力はソリッドのみ（サーフェスだけの形状は不可）
- 動かせる面: 精密は全種類、近似は平面と円筒面のみ
- 近似方式では、動かした面の隣の面は「動かす面の法線方向にまっすぐ」延びる（抜き勾配・フィレットは追従しない）
- 穴やボスの**位置の移動**、フィレット半径の変更は未対応
- 面を大きく動かして隣の面が消える・交差する場合は作れない（範囲チェックで事前に確認）
- 面番号は読み込んだ形状に対して振られる。形状を差し替える・分割角度を変えると定義の面番号がずれるので作り直す
- メッシュ変形は節点を動かすだけなので、大きく動かすと要素がつぶれる（つながりが変わる形・すき間が極端に狭くなる形は作れない）。
  粗い STL（細長い三角形）では特に裏返りやすい
- INP の `*INCLUDE`、`*INSTANCE` の移動・回転には未対応（1 ファイルにまとめた .inp を使う）

## 他のアプリへの埋め込み（ml-process-lab など）

バックエンドは `APIRouter` を返す関数、フロントは 1 つの React コンポーネントになっている。

**バックエンド**（`backend/shapelab/` をコピーし、依存に `cadquery-ocp` `scipy` `python-multipart` を追加）
```python
from pathlib import Path
from shapelab.api import make_router
app.include_router(make_router(Path("data/shape")), prefix="/api/shape")
```

**フロントエンド**（`frontend/src/shapelab/` をコピー。依存は react / three のみ）
```tsx
import { ShapeLab } from './shapelab'
<div style={{ height: '100vh' }}><ShapeLab apiBase="/api/shape" /></div>
```
CSS はすべて `.sl-root` 内・`sl-` 接頭辞なので、埋め込み先のスタイルと衝突しない。

## 構成
```
backend/
  server.py              単体サーバ（/api/shape と画面の配信）
  shapelab/cad.py        CAD 読み書き・面情報・面移動（精密/近似）・メッシュ化
  shapelab/meshio_.py    STL / INP の読み書き（表面の取り出し・節点座標の書き換え）
  shapelab/recognize.py  メッシュの面の自動認識（平面・円筒・円錐・球・トーラス）
  shapelab/meshmorph.py  メッシュ変形（階層的な補間・フィレットの追従）
  shapelab/models.py     CAD とメッシュを同じ操作で扱う入れ物
  shapelab/params.py     寸法パラメータ → 面ごとの移動量
  shapelab/doe.py        実験計画（LHS / ランダム / 格子 / 1因子ずつ）
  shapelab/generate.py   一括生成
  shapelab/api.py        API（make_router）
  shapelab/demo.py       デモ形状
  tests/                 体積の手計算との照合など
frontend/src/shapelab/   画面（React + three.js）: ShapeLab（全体）・Steps（手順）・FacePopup（クリックした面の候補）・suggest（候補の作り方）・dims（3D の寸法矢印）
data/                    models / projects / outputs
```
